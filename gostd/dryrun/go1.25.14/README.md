# Go standard library dry run: go1.25.14

Generated by `tools/gostddryrun` from the Go source tree at `/nix/store/26p9xn49sqb8rbbd2k6jbnzn0rkx3z29-go-1.25.14/share/go`.
Do not edit by hand: rerun the commands at the end of this file.

The `goroot` field of each JSON records the path that was read. It is provenance only: the
same Go version at another path changes it, so ignore it when diffing two Go versions.

## What this is

The input of steps 16.9 to 16.11: everything in Go's standard library that the GC engine
must replace under the build constraints of Phase 16 README 2.7. For each package in the
default set, the tool reports the bodyless functions (with their signatures), every
`//go:linkname` of each kind, the compiler intrinsics, the `.s` files and the packages whose
assembly has no pure-Go fallback, the files that the `gocpp` tag drops or adds compared with
`gc`, and the cgo files. It reads only the source tree: no `go` command, no network.

The default package set is the list of step 16.1 (runtime, reflect, internal/reflectlite,
internal/runtime/maps, sync, internal/sync, time, os, syscall, net, net/http, crypto/tls,
testing) plus the import closure of `net/http` and `crypto/tls`. The closure is walked by
reading the selected files' imports and resolving them in `GOROOT/src` (a vendored package
keeps its `vendor/` path, as Phase 16 README 2.3 rule 4 says).

## Files the `gocpp` tag drops and adds

Compared with the `gc` compiler tag, with every other constraint the same. A file with
`//go:build gc` is dropped under gocpp; a file that gocpp adds has `//go:build gocpp` or
`//go:build !gc`. These are the packages that need an overlay for the file, as Phase 16 README 2.7
describes for `internal/goroot`, `x/sys/cpu` and `x/sys/unix`. The default package set is the
net/http + crypto/tls closure, and `internal/goroot` (the package `go/build` imports) is not in
it, so a zero here is expected. To see those overlays, name the packages:
`-packages internal/goroot,vendor/golang.org/x/sys/cpu`.

them only for `internal/synctest`) and 17 "between other standard packages or to the
linker". The tool does not adjust the plan; it measures three different definitions, none

cannot be reproduced from the plan text; the manager should pick one and update 2.7/7.1.

## Reproduce

```sh
GOROOT=$(scripts/in-devenv go env GOROOT)
GOMAXPROCS=16 go run ./tools/gostddryrun -goroot "$GOROOT" -goos linux -goarch amd64 \
    -out gostd/dryrun/go1.25.14/linux-amd64.json -md gostd/dryrun/go1.25.14/README.md
GOMAXPROCS=16 go run ./tools/gostddryrun -goroot "$GOROOT" -goos windows -goarch amd64 \
    -out gostd/dryrun/go1.25.14/windows-amd64.json -md gostd/dryrun/go1.25.14/README.md
```

The README is written by the last command and reads the JSON files next to it for the
two-target table and the Windows-only section.
