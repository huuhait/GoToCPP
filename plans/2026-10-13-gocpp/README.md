## 1. The idea

**gocpp** is a small programming language that looks and feels like Go. Source files use the
`.gp` extension. The `gocpp` tool translates `.gp` files into normal, readable **C++20** and then
runs a real C++ compiler (`clang++` or `g++`) to build a native program.

You described it correctly: gocpp is a **transpiler** (a source-to-source compiler). It never
writes machine code itself. It writes C++ and lets the C++ compiler do optimization and code
generation. Nim, V and cppfront (Cpp2) use the same approach. (cgo is related but different: it
only compiles the C parts of a Go program with a C compiler.)

Because the output is plain C++, a `.gp` file can **import any C or C++ header**
(`"<vector>"`, `"<SDL2/SDL.h>"`, `"./engine.hpp"`) and call it directly. Any `.c`/`.cpp` file
in the same folder is compiled and linked too. You write Go-style code, and you get C++ speed
plus the whole C/C++ ecosystem.

gocpp is **not** "Go compiled to C++". It keeps Go's *syntax and style* (packages, `:=`,
multiple returns, methods, interfaces, slices, maps, `defer`, goroutines, generics, gofmt
formatting) and drops what doesn't fit C++, such as the garbage collector and full reflection.

It also adds a few things Go doesn't have, all in Go style: **`!` (must)** that returns errors
for you (no more `if err != nil { return err }`), written on a function (`func loadConfig!()`) or
on one call (`os.ReadFile!(path)`); **typed macros** (declared with `macro Name(args) { ... }`,
used as `#Name(...)` inside code, or on top of a func to run at its start or to wrap its code);
and a **language server built to be as fast as gopls**. It targets **Linux and Windows**.

## 2. What it looks like

```go
// main.gp
package main

import (
	"fmt"
	"strings"

	"./physics.h" // your own C header: package physics (physics.c here is compiled too)
	"<cmath>"     // C++ headers make their namespace usable: std.sqrt
	"<vector>"
)

type Vec2 struct {
	X, Y float64
}

func (v Vec2) Len() float64 {
	return std.sqrt(v.X*v.X + v.Y*v.Y)
}

func (v *Vec2) Scale(k float64) {
	v.X *= k
	v.Y *= k
}

func main() {
	v := &Vec2{X: 3, Y: 4}
	v.Scale(2)
	fmt.Println("len:", v.Len())

	nums := std.vector[int]{1, 2, 3} // a real std::vector<int64_t>
	nums.push_back(4)
	for i, n := range nums {
		fmt.Println(i, n)
	}

	physics.step(0.016) // a plain C function from physics.h
	fmt.Println(strings.ToUpper("done"))
}
```

`gocpp emit main.gp` would print C++ like this. It is simplified: real output repeats a `#line`
directive before every generated line, and `struct Vec2` lives in the package header
`gpkg/main/pkg.hpp` (Phase 06).


**Beyond Go (Phase 10):** `!` (must) on a function or a call, and macros declared with `macro`
and used with `#Name(...)` inside code or on top of a func (start style or wrap style):

```go
package main

import (
	"encoding/json"
	"errors"
	"fmt"
	"os"

	"myapp/util"
)

type Config struct{ Port int }

// A macro looks like a func. Inside it, #line() and #text(v) describe where it is used.
macro Dbg[T any](v T) T {
	fmt.Printf("[line %d] %s = %v\n", #line(), #text(v), v)
	return v
}

// ! on a func: every error inside it is returned for you (no `if err != nil`).
#util.Trace() // on top of a func, start style: prints "enter"/"exit" around every call
func loadConfig!(path string) (cfg Config, err error) {
	defer errors.Wrapf(&err, "load config %s", path) // Wrapf(&err, ...) is a gocpp addition
	data := os.ReadFile(path)
	json.Unmarshal(data, &cfg)
	return cfg, nil
}

#util.VM() // wrap style: the macro decides how this code runs (here: inside a VM)
func checkLicense(key string) bool {
	return len(key) == 16
}

func main!() { // ! on main: an error is printed and the program exits 1
	cfg := loadConfig("app.json")
	#util.Assert(cfg.Port > 0, "port must be set")
	fmt.Println("port:", #Dbg(cfg.Port)) // also prints "[line 37] cfg.Port = 8080"
	fmt.Println("license ok:", checkLicense("0123456789abcdef"))
}
```

## 3. Goals and non-goals

**Goals**
- Go syntax and Go style, formatted exactly like gofmt.
- Import any C/C++ header and use it with no glue code. Compile `.c`/`.cpp` files that live
  next to `.gp` files.
- Readable C++ output. `#line` directives make gdb/lldb and compiler errors point at `.gp` lines.
- Native speed, no garbage collector in gp code, deterministic cleanup (reference counting).
  Go packages imported after v1.0 run on a collector of their own (Phase 16).
- Go-like safety by default: bounds checks, nil checks and division checks panic like Go
  instead of crashing randomly (can be turned off for speed).
- One tool: `gocpp build | run | test | fmt | emit | check`.
- An editor experience **as fast as gopls**, with written speed budgets checked in CI
  (Phase 11).
- Less boilerplate than Go without losing Go's style: `!` (must) on functions and calls, and
  typed, tool-friendly macros (Phase 10).
- **Linux and Windows** (x86-64 first): Linux first, Windows before v1.0 (Phase 14).

**Non-goals (for v1)**
- 100% Go compatibility. Existing Go code and Go modules are not expected to build unchanged.
  (After v1.0, Phase 16 plans that for pure-Go modules, on a second engine; cgo, assembly
  without a pure-Go fallback and some crossings, such as most channels, stay out.)
- A garbage collector, full `reflect` (only a subset for `fmt`/`json`/`sort`, see Phase 09) or `plugin`.
  (Phase 16 adds a collector for Go packages only; gp code stays on reference counting.)
- Doing the C++ compiler's job (optimization and machine code stay with clang/gcc).
- macOS (not a target), and MSVC's own compiler (Windows uses MinGW-w64 first; the MSVC ABI
  through `clang-cl` comes later).
- A goroutine scheduler: `go` starts a real OS thread (tens of thousands are fine, millions
  are not).

## 4. How it works (architecture)

```
  .gp files
     │
     ▼
 [1] Parse ─────────── fork of Go's go/scanner + go/parser (3 small patches, 3 more in Phase 10)
     │
     ▼
 [2] Load ──────────── packages + gocpp.mod; imports are gocpp packages or C/C++ headers
     │                 (a header is a package named after its file; C++ namespaces such as
     ▼                  std are packages too, without an import)
 [2b] Expand ───────── macro decls → funcs, #Name(...) → calls (start / wrap style),
     │                 #Derive → methods, F!() and func f!() → error checks
     ▼                 (Phase 10; cached per file, keyed also by the macro signatures used)
 [3] Type-check ────── stock go/types (FakeImportC): Go rules for gocpp code,
     │                 C/C++ names are "opaque" and checked later by the C++ compiler
     ▼                 (Phase 12 adds real C++ types from clang)
 [4] Lower ─────────── Go semantics → C++-friendly form: evaluation order, closures,
     │                 boxing of address-taken variables, defer frames, range loops
     ▼
 [5] Emit C++ ──────── one .hpp per package + one .cpp per .gp file + #line directives
     │
     ▼
 [6] Build ─────────── clang++/g++ -std=c++20 (parallel, cached), also compiles the
     │                 package's .c/.cpp files and links libs (pkg-config, -l...)
     ▼
  native executable / static lib / shared lib
```

The **runtime** (`gp::` namespace) is a C++20 library, mostly headers, shipped inside the
`gocpp` binary. It provides `gp::string`, `gp::slice`, `gp::map`, `gp::ptr`, interfaces, panics,
defer frames, channels and goroutines. The **standard library** (`fmt`, `strings`, `os`, ...)
is written mostly in gocpp itself and calls C/C++ where needed.

## 5. Key decisions (details and alternatives in Phase 00)

| Topic | Decision | Why |
|---|---|---|
| Compiler written in | **Go** | You like Go; Go ships its own parser and type checker as libraries |
| Parser | **Fork of `go/scanner` + `go/parser`**, stock `go/ast` | Battle-tested Go grammar; 3 small patches in Phase 01, 3 more plus a small `go/printer` fork in Phase 10 |
| Type checker | **Stock `go/types`** with `FakeImportC`. Phase 12 adds C/C++ types in a separate interop checker; no fork (a fork would cut us off from x/tools: the language server's export data and `gocpp vet`) | Full Go typing rules (generics, constants, embedding) for free |
| Output | **Readable C++20** with `#line` | Debuggable, trustworthy, links with anything |
| Memory | **Automatic reference counting** (`gp::ptr<T>` over `std::shared_ptr`) | No GC, deterministic. No use-after-free in gocpp code, except data races, `unsafe` and C/C++ values. Reference cycles leak unless broken with `weak.Pointer`. After v1.0, Phase 16 runs Go packages on a second engine with a garbage collector; gp code stays on ARC |
| C/C++ access | `import "<raylib.h>"`, `import "./x.h"`: **a header is a package** named after its file (`raylib.InitWindow`), and **C++ namespaces are packages** (`std.vector`); `C` keeps only C's built-in types (`C.int`) and helpers | Looks exactly like using Go packages, works for almost all C/C++ (a few gaps until Phase 12) |
| Errors | Go `error` values; `panic` = C++ exception; `defer` = frame object | Go style; a panic costs nothing until it is thrown (each `defer` costs a little) |
| Goroutines | **OS threads**: `go f()` starts a real thread; no goroutine scheduler, now or later | Simple, robust, easy to debug; tens of thousands of goroutines are fine |
| Build | `gocpp` calls clang++/g++ itself, with a content-hash cache | `go build` feel; exports `compile_commands.json` and CMake |
| Error sugar | **`!` (must)**, only where written: `func f!() T` returns every error dropped inside it; `F!(...)` returns one call's error; `main` prints the error and exits 1 | A long-requested Go feature, marked where it acts, zero runtime cost |
| Macros | **`macro Name(args) { ... }`**, used as `#Name(...)` inside code or on top of a func (start style, or wrap style with `#body()`, e.g. `#VM()`); `#Derive(...)` on types | Macro power without breaking types, gofmt or the editor |
| Platforms | **Linux and Windows** (x86-64 first); Windows through MinGW-w64, ported in Phase 14; no macOS | Your targets; the runtime reaches the OS through one small layer from day one |
| Language server | **gopls architecture** (snapshots, content-hash caches, export-data summaries), speed budgets in CI | Same engine as gopls: re-checking `net/http` (28.5k lines) takes ~30 ms |

## 6. Type mapping cheat sheet

| gocpp (`.gp`) | Generated C++ |
|---|---|
| `int`, `uint` | `int64_t`, `uint64_t` (64-bit targets, like Go) |
| `int8` … `int64`, `uint8` … `uint64`, `uintptr` | `int8_t` … `int64_t`, `uint8_t` … `uint64_t`, `uintptr_t` |
| `byte`, `rune` | `uint8_t`, `int32_t` |
| `float32`, `float64`, `complex64`, `complex128` | `float`, `double`, `std::complex<float>`, `std::complex<double>` |
| `bool` | `bool` |
| `string` | `gp::string` (immutable bytes, usually UTF-8; cheap substrings) |
| `[N]T` | `gp::array<T, N>` (value type, bounds checked) |
| `[]T` | `gp::slice<T>` |
| `map[K]V` | `gp::map<K, V>` (reference type) |
| `*T` where `T` is a gocpp type | `gp::ptr<T>` (reference counted, nil-checked) |
| `*pkg.T` where `T` is a C/C++ type (`*SDL.SDL_Window`, `*cstdio.FILE`) | `T*` (raw pointer, C++ rules) |
| `unsafe.Pointer` | `gp::ptr<void>` (keeps a gocpp object alive, like Go) |
| `func(A) R` | `gp::func<R(A)>` |
| `struct{...}` | `struct` + generated `==`, hash, field info |
| `type Celsius float64` (named non-struct type) | `struct Celsius : gp::newtype<Celsius, double>` (a distinct type that can have methods) |
| `interface{...}`, `any`, `error` | generated interface class, `gp::any`, `gp::error` |
| `chan T` | `gp::chan<T>` |
| results `(A, B)` | `std::tuple<A, B>` |
| `C.int`, `C.char`, `C.size_t`, … (C's built-in types) | `int`, `char`, `size_t`, … (same names as cgo) |
| `std.vector[int]` | `std::vector<int64_t>` |

Some different Go types share one C++ type (`int` and `int64` are both `int64_t`). They stay
different where Go can tell them apart (`any(int(1)) != any(int64(1))`, type switches, `%T`),
because interface values carry a type descriptor chosen by the **Go** type (Phase 05).

## 7. Already validated (spike on 2026-10-13)

While writing this plan, small throwaway programs (spikes) tested the riskiest assumptions on
this machine (Go 1.25.7, clang 21.1.8, GCC 15.2). The most important was that Go's own front-end
can parse and type-check `.gp` files that mix Go code with C/C++ symbols. The others covered clang
probing, formatting, and Go output details the runtime must copy exactly.

| Check | Result |
|---|---|
| Stock `go/parser` accepts `"<vector>"`, `"<SDL2/SDL.h>"`, `"./native/physics.h"` import paths | OK |
| Stock `go/parser` accepts `std.array[int, 5]` (C++ non-type template argument) | FAIL (`expected type, found 5`), so parser patch #2 |
| Stock `go/parser` accepts `std.map[...]`, `node.type()` (Go keywords as C++ names) | FAIL, so parser patch #1 |
| Stock `go/parser` accepts more than one dot in a *type* (`var d std.chrono.seconds`, `[]std.chrono.seconds`) | FAIL (found in the audit), so parser patch #3 |
| `std.get[0](t)`, `lib.arr[3]`, `std.vector[std.vector[int]]{}` | OK |
| Stock `go/types` + `FakeImportC` on a realistic file (header packages `SDL`, `cstdio`, `physics`, namespaces `std` and `std.filesystem`), after the Phase 01 rewrite; re-run with the final import model | OK, **0 errors** |
| Namespace probe: are `std`, `stdd`, `fmtt` C++ namespaces? (one `-fsyntax-only` file, clang++ and g++) | `std` yes; `stdd` and `fmtt` no, so they're reported as `undefined` (typos stay early errors) |

| C macro as array length (`[cstdio.BUFSIZ]byte`) | PARTIAL: no error, but no value, so it needs Phase 12 probes |
| clang "type probe" `decltype(std::minmax(1,2))` | `std::pair<const int &, const int &>` in 0.12 s |

## 9. How to use this plan

## 11. Prior art worth studying

- **cgo**: the `C.` pseudo-package (gocpp keeps it for C's built-in types like `C.int` and for
  `C.CString`/`C.GoString`).
- **V (vlang)**: Go-like syntax compiled to C, with `C.` calls.
- **Nim**: compiles to C/C++ with deep C++ interop pragmas.
- **Carbon**: C++ interop through a `Cpp.` package (`Cpp.std.vector`).
- **cppfront (Cpp2)**: a new syntax transpiled to C++ that mixes freely with normal C++.
- **Zig**: `@cImport` uses clang to understand C headers.
- **TinyGo**: Go front-end (`go/types`) plus clang for cgo headers.
- **GopherJS**: `go/types`-checked Go code emitted as readable JavaScript (same shape as gocpp).
