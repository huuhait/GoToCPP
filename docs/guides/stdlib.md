# The standard library

The library is a **subset of Go 1.25.14**, not a promise that every Go import or every exported
API works. Most packages are Go source ported into `.gp`; the system and runtime interfaces
are smaller implementations. `fmt` is deliberately native, not Go's package compiled through
`reflect`. Use the [API reference](../stdlib/index.html) for declarations, this page for status
and differences, and the [porting guide](porting.md) to add a package.

**Experimental:** the Phase 09 packages still need `GOCPP_GATE_PHASE=09`. The
[feature matrix](../spec/feature-matrix.md) gives the gate for each package. A declaration in the
reference is not by itself an implementation: `embed` is a stub, while the compiler/runtime
implement the declaration shims `fmt` and `weak` specially. The compiler already supports
[`//go:embed` into strings/bytes and `#embed`](embed.md); the missing API is `embed.FS`, not
embedding file bytes.

## Reading the inventory

The tables include every directory of `stdlib/` with non-test `.gp` files, including internal
support packages. `unsafe` is a language-provided package, not a directory of this tree.

- **port** means generated by `tools/portstd`, checked in `stdlib/PORTED.txt` and
  `PORTED.sha256`. **Go copy** means copied/adapted by hand, not reproducible by `portstd` yet.
  **native** means C++ runtime code supplies functions. **shim** means a smaller compatibility
  surface; **stub** has declarations but no implementation. These are implementation styles,
  not completeness ratings. No package in this inventory is implemented primarily through
  header imports; C/C++ interop is available to applications but is not the `os` implementation.
- **Source / port selection** links to the package's `PORT.md` (or source when it has none).
  Parent `PORT.md` files cover groups of shims. The parenthesized GOOS is the actual
  `portstd` selection recorded in `PORTED.txt`, **not** a restriction to that runtime OS:
  portable packages selected on Linux also build for Windows. The tool normally selects
  `arch=generic,tags=purego`; `encoding/binary` selects `amd64`, and `math/bits` also uses
  `compiler_bootstrap`. See each port's record for the exact inputs and patches.
- **Targets** lists Linux/Windows source selections on `amd64`, using the loader's build-tag
  rules. This checks that a package has selected source, **not** that every API or dependency
  has been exercised on both systems. The supported platform matrix and real-Windows checks
  are in the [Windows guide](windows.md). In particular, `time.Local` is UTC on Windows (below).
- **Tier** is the schedule from [Phase 09 §2.6](../../plans/2026-10-13-gocpp/phase-09-stdlib-testing/README.md#26-package-tiers),
  not a quality score. `support` means the package is outside those named tier lists.
- **Manifest selected / all** counts runnable top-level test/example/fuzz functions from
  `tests/stdgo/manifest`, including functions dropped from selected files in the numerator.
  It is **not a pass count**. `—` means no manifest, not "untested". The
  [test report](stdlib-tests.md#results) records the measured Linux results, exclusions and
  divergences. Notably `fmt`, `sync`, `sync/atomic` and `testing` have other tests but no such
  manifest; `os` passed 91.1% of selected functions but only 58.6% of all functions in that report.

The inventory is checked against the tree, provenance, plan tiers and manifests without running
C++ tests. Regenerate only the marked tables after changing those inputs:

```sh
go test ./tools/docsite -run '^TestStdlibGuideInventory$'
UPDATE_STDLIB_GUIDE=1 go test ./tools/docsite -run '^TestStdlibGuideInventory$'
```

## Packages that are not shipped

This is the practical missing-package list, not every absent member of Go's library. An internal
or test-only copy is **not** a supported application import. For example `tests/stdgo/math/big`,
`testing/iotest`, `testing/fstest`, `math/cmplx` and `compress/bzip2` only support converted tests;
`tests/stdgo/crypto/sha1` is a test shim, not a cryptographic implementation.

| Package or family | Why it is absent / current plan |
|---|---|
| `crypto`, `crypto/sha256`, `crypto/md5`, `crypto/sha1`, `crypto/rand` | No production port. `sha256` and `md5` were tier 2 but remain deferred; Go 1.25's FIPS/runtime dependency tree needs a deliberate generic port or a library wrapper, not a copy of a test shim. |
| `os/exec` | Tier 2, deferred. `os.StartProcess` returns `ENOSYS`; process creation is not supplied by the current `os` port. |
| `os/signal` | Tier 3, deferred; no public signal-delivery package. |
| `net`, `net/url` | `net` is tier 3; no production sockets package or URL port. The file-polling support used by `os` is not `net`. |
| `net/http` | Not planned for this release; use a C/C++ HTTP library through interop or a later wrapper. |
| `encoding/csv`, `compress/gzip`, `archive/zip` | Tier 3, not ported. |
| `text/template`, `html`, `html/template`, `math/big`, `math/cmplx`, `image`, `mime`, `os/user` | Outside the shipped port set; no production implementation. |
| `hash/maphash`, `hash/adler32`, `hash/crc64` | Deferred after the current tier-2 work. |
| `testing/iotest`, `testing/fstest`, `testing/quick`, `testing/synctest` | No shipped package; some converted tests have test-only helpers. No Go scheduler/synctest bubble implementation. |
| `time/tzdata` | The embedded timezone hook is not supplied; use `ZONEINFO` or Linux's zone database. |
| `plugin`, `go/*` | Outside the release plan. Reflection is descriptor-based; no full dynamic reflection, runtime code generation or dynamic Go plugin loader. |

The package presence checks of [the Go developer guide](go-developers.md#what-is-not-there)
cover common unavailable imports even with all phase gates open. The generated
[dependency/blocker audit](porting-blockers.md) is an upstream porting analysis, **not** a live
list of missing shipped packages; a blocker there may already have a shim here.

## What differs from Go

These are implementation contracts or known gaps, not suggestions to silently patch away a
failing Go test. The [language differences](go-developers.md#what-is-different) and
[Go-test counting rule](stdlib-tests.md#the-counting-rule) apply alongside them. Source links
below point to the implementation; linked tests are existing evidence, not a claim that this
page reran all those suites.

| Area | Current behavior | Implementation and evidence |
|---|---|---|
| Memory | Automatic reference counting, not tracing GC. Reference cycles leak unless broken (for example with `weak.Pointer`). `runtime.GC` does nothing; `SetFinalizer` never runs a finalizer. Close files explicitly: dropping an `os.File` does not close it. | [D1](../spec/language.md#d1-reference-counting-instead-of-a-garbage-collector), [runtime natives](../../runtime/src/runtimepkg.cpp), [OS port](../../stdlib/os/PORT.md), [ARC tests](../../runtime/test/unsafe_test.cpp). |
| Goroutines and stacks | One OS thread per goroutine, not Go's multiplexed scheduler. The default goroutine stack is a fixed 8 MiB (not a growing Go stack). Deep recursion and large value temporaries can overflow it; do not translate Go's goroutine-count or recursion assumptions directly. | [D7](../spec/language.md#d7-goroutines-are-os-threads), [D24](../spec/language.md#d24-large-values-on-the-c-stack), [stack constants](../../runtime/include/gocpp/goroutine.hpp), [thread implementation](../../runtime/src/os/linux/thread.cpp). |
| Runtime controls | `GOMAXPROCS` remembers a value but does not limit running threads. `LockOSThread`, `UnlockOSThread`, `KeepAlive` are no-ops. `Stack(buf, true)` only reports the caller. `ReadMemStats` supplies a subset of allocator fields; it is not Go's GC accounting. `AddCleanup` and profiling/trace APIs are incomplete or absent. | [runtime port](../../stdlib/runtime/PORT.md), [native API](../../runtime/include/gocpp/runtimepkg.hpp), [runtime tests](../../runtime/test/runtimepkg_test.cpp). |
| `GODEBUG` | Not Go's runtime-wide compatibility/configuration system. `internal/godebug.Setting.Value` reads the environment, but has no Go defaults/metrics/runtime hooks; only a consumer that actually calls it can use a setting. In particular `time` does not implement `asynctimerchan` (it uses Go 1.23+ timer semantics). | [godebug shim](../../stdlib/internal/godebug/godebug.gp), [time port](../../stdlib/time/PORT.md). |
| `fmt` | Native print/scan engine over descriptors, including foreign C/C++ values. Go-style verbs and error text do not imply identical internals: scan number errors are plain errors, not `*strconv.NumError`; allocation counts, very deep nesting and some saved-state/racing uses differ. `Print*` follows reassignment of `os.Stdout`, and `Scan*` follows `os.Stdin`. | [ADR-100](../adr/100-fmt-stays-native-decision-9-7-a.md), [fmt port record](../../stdlib/fmt/PORT.md), [Go test fixture](../../tests/gotest/testdata/fmt_gotest/fmt_test.gp). |
| `os` / `syscall` | Go-derived file APIs over a smaller native syscall layer on Linux and Windows. No `os.Root`, `OpenRoot`, `OpenInRoot`; `StartProcess` returns `ENOSYS`. `RemoveAll` walks paths instead of Go's `*at` implementation and can fail past `PATH_MAX` on Linux. Linux pollable files support close-wakeup and deadlines; regular files do not. Windows uses synchronous handles, not arbitrary overlapped handles. | [OS port and limitations](../../stdlib/os/PORT.md), [poll implementation](../../stdlib/internal/poll/PORT.md), [process implementation](../../stdlib/os/process_unix.gp), [Linux poll tests](../../tests/run/os_poll_deadline.gp). |
| Time zones | Linux loads `ZONEINFO`, then standard system zoneinfo paths. No bundled `time/tzdata` or `$GOROOT/lib/time/zoneinfo.zip` fallback. Windows has no registry zone discovery: `Local` is UTC, and named zones need `ZONEINFO`. | [Linux zone sources](../../stdlib/time/zoneinfo_unix.gp), [Windows zone sources](../../stdlib/time/zoneinfo_windows.gp), [lookup order](../../stdlib/time/zoneinfo.gp), [zone tests](../../tests/stdgo/time/zoneinfo_test.gp). |
| `reflect` | Enough descriptors, accessors and setters for the current consumers, not full reflection. No `Value.Call`, `Value.Method`, `MakeFunc`, `StructOf`, `FuncOf`, dynamic channel operations or general type construction. `Type.Method` metadata is not callable (`Type` is nil). | [D6](../spec/language.md#d6-a-reflect-subset-and-no-plugin), [reflect declarations](../../stdlib/reflect/type.gp), [value declarations](../../stdlib/reflect/value.gp), [ADR-035](../adr/035-reflect-subset-on-descriptors.md). |
| `unsafe` and layout | `unsafe.Pointer` and slices/strings derived from owning gocpp pointers retain ownership. Ordinary raw C pointers and pointers reconstructed from unregistered `uintptr` addresses do not recover an owner. At the exact address of a registered, still-live gocpp-owned C/C++ box, conversion back to a gocpp pointer recovers and retains that box's owner. A `uintptr` itself never keeps memory alive: retain an owner across the raw-address interval; do not assume arbitrary or interior addresses recover one. `Sizeof`, `Alignof` and `Offsetof` use gocpp/C++ layouts, not Go's ABI (for example string 32, slice 40, pointer 16 bytes on the supported 64-bit targets). | [D15](../spec/language.md#d15-different-sizes), [D16](../spec/language.md#d16-unsafepointer-and-pointers-from-c), [address conversion](../../runtime/include/gocpp/unsafe.hpp), [owner recovery](../../runtime/include/gocpp/ptr.hpp). |
| `sync` | Mutex/RWMutex/WaitGroup/Cond use native implementations of Go's algorithms; `Map` uses a lock (its `Range` walks a cached list of the entries) and `Pool` is bounded, not GC-cleared. Internal layouts and allocation behavior differ. | [sync port](../../stdlib/sync/PORT.md), [ADR-040](../adr/040-sync-on-a-semaphore-table.md). |
| `math` | A Go-source port with native instruction/assembly equivalents, not an arbitrary `libm` wrapper. The intended contract is Go amd64's results bit for bit, including its known subnormal `Log` behavior; operator-produced NaN payloads are outside that contract. | [math port](../../stdlib/math/PORT.md), [ADR-071](../adr/071-math-bit-exact.md). |
| Builtin `print` / `println` | Debugging builtins, not `fmt`. Slices and maps are rejected (D23); printing interface operands is also an open compiler gap. Use `fmt.Print*` for application output and converted tests. | [D23](../spec/language.md#d23-print-and-println-of-a-slice-or-a-map), [print lowering](../../internal/lower/builtins.go), [recorded test gap](stdlib-tests.md#what-fails-and-why). |
| Testing | `_test.gp`, examples and fuzz seed corpora run; the fuzzing engine, coverage, JSON output and several other Go flags do not. Allocation counts measure C++ `operator new`, not Go allocation decisions. `T.Context` / `T.Output` are not implemented. | [testing differences](testing.md#what-differs-from-go), [testing port](../../stdlib/testing/PORT.md), [counting rule](stdlib-tests.md#the-counting-rule). |

For a package port, first establish whether the failing behavior is a compiler bug, a missing
runtime facility or one of these explicit divergences. Record the distinction in `PORT.md` and
in the test-conversion specification; a compile error or an ordinary skip never becomes a pass
merely because it is documented.
