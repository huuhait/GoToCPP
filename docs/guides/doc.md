# `gocpp doc`: documentation in the terminal

`gocpp doc` shows the documentation comments of a package or of one name in it, like `go doc`
does for Go. For the same source it prints **the same text as `go doc`**, byte for byte: the
declarations come from gocpp's own printer, the comments from `go/doc` and `go/doc/comment`
(80 columns, the same indentation, lists, headings and code blocks). A test compares the two on
a module of about two dozen packages and 1299 invocations of every flag and name.

```
gocpp doc [flags] [package|[package.]symbol[.methodOrField]]
```

## Find a package or a name

| You type | You get |
|---|---|
| `gocpp doc` | the package in the current folder |
| `gocpp doc strings` | the package comment and a one-line summary of every exported name |
| `gocpp doc strings.Builder` | the type, its fields and a summary of its methods |
| `gocpp doc strings.Builder.WriteString` | one method (`Type.Field` shows a field) |
| `gocpp doc Builder` | a name in the package of the current folder (a name that starts with a capital) |
| `gocpp doc encoding/json Marshal` | two arguments: a full package path, then the name |
| `gocpp doc ./geom` | a folder |

A package path may be partial: `json` finds `encoding/json`, `geom` finds
`example.com/app/geom`. The places that are searched, in this order, are the standard library
(embedded in gocpp, documented from its own `.gp` files), the main module (the nearest
`gocpp.mod`), and the modules it requires (replaced folders, `vendor/`, the module cache). If the
name is not in the first package that matches, the next one is tried; when none has it, the
message lists the packages that were searched (`no symbol Nope in packages a/util, b/util`).

A name without capital letters matches in either case (`gocpp doc json.marshal`); `-c` makes the
match exact. `-h` prints the help.

## Flags

| Flag | Meaning |
|---|---|
| `-all` | all the documentation of the package (every comment, not only the summary) |
| `-src` | the source of the name, as written, with its comment |
| `-u` | unexported names too (and fields, methods) |
| `-short` | one line for each name |
| `-c` | the match of names is exact |
| `-cmd` | show the names of a command (`package main`); they are hidden by default |
| `-C dir` | run in `dir` |
| `-examples` | (gocpp only) list the examples of the `_test.gp` files: with `-all` with their code and output |

The files read are the `.gp` files that the build constraints of the target keep (`GOOS`,
`GOARCH`; `_linux.gp`, `//go:build`). The compiler is `gocpp`, as for the build: the tags `gc` and
`cgo` are **false**, so a file with `//go:build gc` or `//go:build cgo` is hidden (`go doc` shows
it; this is by design, the loader does the same). The rule is `load.MatchFile`.

Exit status: 0 when something was shown; 1 when the package or the name was not found; 2 for a
mistake in the command line (too many arguments, a name with too many periods, an unknown flag).

## What only gocpp has

Everything that Phase 10 adds to the syntax is shown as it is written:

```
$ gocpp doc -all macros
func Parse!(s string) int
    Parse reads a number. It fails with ErrSyntax when s is not one.

macro Assert(cond bool, msg lazy string)
    Assert stops the program when cond is false.

#Trace()
func Run()
    Run does the work and traces it.

#Derive(String, Equal, Clone)
type Point struct {
	X, Y int
}
    Point is a point of the plane.

func (p Point) Equal(other Point) bool
    Equal is generated by #Derive(Equal).
```

- `func f!() T` keeps its `!`; `gocpp doc pkg.f` and `pkg.f!` both find it.
- A macro is listed with the functions, as `macro Name(params)`; find it with `pkg.Assert` or
  `pkg.#Assert`. A macro on top of a func or a type (`#Trace()`, `#Derive(...)`) is printed above
  the declaration.
- The methods that `#Derive(String | Equal | Clone | JSON)` generates are listed with the methods
  of the type, with the comment "generated by #Derive(...)", although no `.gp` file has them
  until `gocpp expand`.
- Generic functions and types print their type parameters and constraints.

## C and C++ headers

A header is an *opaque package*: gocpp does not read it, so it has no declarations to print.
`gocpp doc` says what it can:

```
$ gocpp doc '<stdio.h>'
header <stdio.h>

Opaque package: gocpp does not read what the header declares, so it has no
documentation for it; the C++ compiler checks the names that a file uses.

Package name: stdio
Header file: /usr/include/stdio.h

$ gocpp doc -all ./physics.h          # a header of your own: its Doxygen comments
$ gocpp doc ./physics.h vec_add       # the comment of one name
$ gocpp doc '<vector>' std.vector     # ask the C++ compiler what the name is
std.vector: a class or alias template (spelled name[args] in a .gp file), declared after #include <vector>
$ gocpp doc std                       # the C++ namespace std
```

The comments that are shown are the Doxygen ones (`///`, `//!`, `/** */`, `/*! */`) that stand
directly above a declaration, read from the header file itself (not from the headers it
includes). The header file of a system header is found with the C++ compiler of the target. A
header of a module is `gocpp doc github.com/x/y/z.h`.

## From an editor or a tool: `internal/doc`

The command is a thin layer over `internal/doc`:

- `doc.Run(w, env, opts, args)` is the command without the flags parsing.
- `doc.Render(w, pkg, symbol, opts)` writes the documentation of one name of a `doc.Package`
  that the caller read: files from the disk or the buffers of an editor (`doc.File` holds the
  text). The language server can use it for hover texts. It does not depend on `Env`, and a
  `Package` can be rendered again and in parallel.
- `Env.ReadDir(fsys, dir, importPath)` reads a package folder with the build constraints.

## Differences from `go doc`

- Files that need the tags `gc` or `cgo` are hidden (see above).
- `#Derive` on a type group (`type ( A int; B int )`) shows no derived methods: the spec puts
  `#Derive` on top of one type, so only the macro lines above a single `type T ...` declaration
  add methods, and the macro line above a group is not printed either (a test pins it).
- `import "."` comments: `go doc` prints `package p // import "x"` from the import comment when
  there is one; gocpp has none and always prints the import path.
- A header that the C++ compiler does not find (`gocpp doc <nosuch.h>`) is an error (exit 1); a
  folder that cannot be read during the search is told on the standard error as
  `gocpp doc: open DIR: permission denied`, and the search goes on.
- A folder with only `_test.gp` files says `no source-code package in directory D`.

- The source is `.gp` files, parsed with gocpp's parser (Phase 10 syntax).
- An error names a package by its import path (`no symbol X in package example.com/app/geom`);
  `go doc` prints the folder it found with `go list`, or `.`.
- No `-http`, and no GOPATH import comments.
- The name of a package can also be a header or a C++ namespace (above).
