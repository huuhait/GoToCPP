# ADR-117: Typed probes load a precompiled library block; type dumps keep the full preamble

Status: accepted, revised after round-2 review (2026-10-20). Step 12.14. Builds on [ADR-088](088-typed-interop-caches-every-compiler-answer-per-reference-under-the-headers-contents.md) (the probe cache and its dependency lists) and [ADR-108](108-typed-interop-becomes-the-default-when-three-measurements-pass-and-the-clang-policy-is-a-matrix.md) (measurement 2, the cold cost). The contract is in [typed-interop.md](../spec/typed-interop.md) §2.2, §9 and §14.3. The filename is retained for existing links; the smaller-preamble decision it originally described is withdrawn.

## Context

The Phase 12 exit criterion says cold probing takes under 0.5 s per example package. Step 12.12 measured 0.5 s for `multi-pkg` and 1.0 to 2.0 s for the other four examples, and ADR-108 made that the first of the three reasons for keeping opaque the default. A timing wrapper around the compiler (`GOCPP_CLANG`) showed where the time goes:

- A typed check runs clang++ about a dozen times in stages: the kind probe (Phase 06, also run by opaque mode), then the probe stage (the expression probes and the overload sets of functions, in parallel), then rounds of declaration dumps (one run per last type name, in parallel inside a round, a new round when a type names others), plus preprocessor-only runs (`-E -v`, `-E -dI`, `-E`).
- Every generated file starts with the same block of 18 library headers (`<string>`, `<vector>`, `<memory>`, `<span>`, ...), and clang parses it again in every run: historically 0.30 to 0.35 s of the 0.35 to 0.45 s that a run takes for a package that has no library headers of its own.
- The `-E -dI` question (what the package's includes include, for the places where a header could be hidden) ran after the compiler run that needed its answer, on the critical path.

## Options

1. **A precompiled header (PCH) of the block, content-addressed in the probe cache, loaded by the probe runs.** Chosen for the probe and function runs. Historically a run on it took 0.06 to 0.15 s instead of 0.33 s.
2. **The same PCH for the declaration dumps of types.** Rejected: clang reads the members of a class, struct or enum that comes from a PCH only when something uses them, and the JSON dump prints the members read so far. `std::mutex` came out without its methods, `struct _IO_FILE` with a tenth of its fields, `std::basic_string_view<char>` without its methods. No flag helps (`-ast-dump-all=json` is the same: the JSON dumper ignores the deserialize setting), and a trigger in the source is not general.
3. **A smaller preamble for the type runs of the package's own types.** Withdrawn as unsound, including its preprocessor-equivalence test and error fallback. Macros and include order can change a successful answer; even equal preprocessed text and final macros do not imply equal C++ lookup. The reviewer's header declares `using namespace std; template<class T> concept HasBegin = requires(T &x) { begin(x); }; struct Mode { int a; conditional_t<HasBegin<int[2]>, long, char> b; };`. The full block supplies `std::begin`: both type runs succeed, but on the reviewed Linux target the full block gives size/alignment 16/8 and the smaller block gives 8/4. Both GCC and Clang runtime preludes agree with 16/8. The old approval memo also omitted dependency contents, so a header edit could reuse an obsolete approval. All of that optimization and its approval memo are removed, not replaced by another textual heuristic.
4. **A PCH of the block plus the package's headers, made per package.** Historically it saved 0.1 to 0.2 s in each stage but cost 0.6 s to make; a cold package cannot win, and type runs could not load it anyway (option 2). Not done.
5. **Merge the stages into fewer compiler runs.** The kind probe is Phase 06's and opaque mode runs it too; the probe lines depend on its answers. A merged file would have to carry every probe in every plausible kind. Too invasive for this step, not done.
6. **Speculative kind probing while Go checks the package.** Not done; a possible next step.
7. **C++20 header units / modules.** Not stable across the compilers and versions in the matrix. Not done.

## Decision

- **PCH of the block** (`probe/pch.go`). Built with `-x c++-header -fvalidate-ast-input-files-content` and loaded with `-include-pch` by the probe runs and the function runs. The generated files keep their `#include` lines, so no line moves.
  - *Where and key.* `<probe cache>/pch/ab/<hash>.{pch,hpp,json}`. The key is the compiler, flags, include-path environment, toolchain and block text, not the package folder. It is **per compiler and flag set**: packages with the same flags share it; different `pkg-config` flags need another header. Validity includes content hashes and the places where another header would hide an input (`finalDeps`). A library header edit or an earlier shadow invalidates it. Its description includes the `.pch` size, so a cut-off file is not used.
  - *Concurrency.* One build per key per process, a lock per key between processes, a second lookup after acquiring the lock, temporary files renamed into place. The newest 4 headers are kept. Orphaned files from a killed build are pruned after 10 minutes.
  - *Dependencies of results do not change.* Files the PCH read are added to the run's dependencies; its generated source is excluded. Results with and without a PCH share the same keys and dependencies.
  - *Refusal.* A run that loaded the header, made no declaration and failed is retried without it. A program failure that repeats does not invalidate the header; a PCH refusal or a successful retry does. After two refusals the process stops using that file.
  - *Waiting.* A run starts without a newly building header. A build at least 200 ms old can be waited for, at most 400 ms. `GOCPP_PROBE_PCH=wait` forces waiting; `off`, `0`, `false` and `no` disable PCH use only. A call waits for its builds (`WaitPCH`, at most 6 s before cancellation); an interrupted command cancels its build. No PCH is used without a cache folder, with a non-Clang compiler, with `-march=native`, or with a relative include-search path.
  - *When.* The kind probe's first miss starts the build (`interop.WithMissHook`). The build and the hook's toolchain question run outside the `Jobs()` gate, at most one build per key and process.
- **Type dumps always parse the full library preamble**, without a PCH, regardless of the spelling of the requested type. This preserves C++ lookup and header-order semantics and lets Clang dump all members. The ordinary declaration cache is still keyed by generated text and dependency contents; a same-Runner edit invalidates it.
- **The includes question is asked beside the compile** (`probe/includes.go`, `prefetchInfo`). Concurrent runs of a preamble started within a second share one question; a still-valid answer skips it. Header edits during the question prevent memoization (`racyDeps`). Each caller owns one reference and computes completeness on its own copy of the immutable scanner result. A canceled await returns incomplete information, releases only that reference, and cannot store a canceled answer or compiler result. The auxiliary compiler is canceled and joined only when the last reference leaves; another live waiter can still get the complete result.

## Consequences

- **Correctness takes precedence over the smaller preamble's savings.** Every type dump pays full parsing again. PCH acceleration for expression/function runs and include prefetch remain independently useful, but their savings do not establish the all-example cold target. No warm or retained-PCH result counts as a fully cold result.
- **Acceptance remains open.** The old all-example table in §14.3 is explicitly historical, from the withdrawn smaller-preamble implementation. Round 3 remeasured only `raylib`: two medians of 7 fully cold typed checks were 911.5 and 917.3 ms versus 62.22 and 65.30 ms opaque, a typed-minus-opaque difference of 0.849–0.852 s. Retaining a PCH gave 710.7–714.1 ms but is partial-cache, not fully cold. Warm overhead was 20–21 ms for this example. Other rows need fresh measurements before making current performance claims; the <0.5 s cold criterion is not accepted.
- **Warm behavior remains compiler-free** when ordinary result caches hit. Full type preambles do not add warm compiler runs.
- **Oracle evidence is scoped.** The earlier phase-12 oracle compared 286 programs but did not cover the successful lookup counterexample. The updated oracle requires equal declaration dependencies too; it no longer permits the old smaller-preamble subset exception. Only its `examples_raylib_main.gp` case was rerun in round 3 and passed; no whole-corpus rerun is claimed. Focused tests cover the lookup regression, same-Runner header editing, preprocessor-sensitive headers, PCH answer/member preservation, and canceled/shared include waiters.
- **Disk.** Up to 4 PCH files of about 8 MB each; `gocpp clean -cache` removes them.
- **Compilers.** PCH is Clang's mechanism, independent of the build compiler. Current focused checks use Clang 21; Clang 17 to 20 remain untested.
- **Further work** could investigate speculative kind probing and a package-specific probe-stage PCH. Neither restores the rejected type-dump shortcuts.

## Evidence
