# ADR-131: Typed interop is the default mode

Status: accepted (2026-10-21; user decision: "it must be default"). Supersedes the default part (decision 4) of [ADR-101](101-the-interop-mode-is-chosen-by-a-flag-and-falls-back-to-opaque-without-clang.md) and the proposal of [ADR-108](108-typed-interop-becomes-the-default-when-three-measurements-pass-and-the-clang-policy-is-a-matrix.md), which wanted the flip only after three measurements; the user took its option 1 (`auto` is the default) now and accepted the measured cold cost. The cold-probing numbers are [ADR-121](121-cold-typed-probing-floors-the-signature-chain-and-precompiled-type-dumps-of-program-types.md)'s. The contract is [typed-interop.md](../spec/typed-interop.md) §13.

## Context

ADR-101 built the flag `-interop=typed|opaque|auto` and `GOCPP_INTEROP`, left `typedinterop.DefaultMode = Opaque` and listed what the switch needs: one constant and the words of the documents. ADR-108 proposed to flip it when a clang 17 to latest matrix, cold probing under 0.5 s and a Windows host were shown. ADR-121 measured the cold cost (typed minus opaque, fully cold: `raylib` 0.66 s, `sqlite` 0.65 s, `multi-pkg` 0.47 s, `mixed-sources` 1.17 s, `cpp-std` 1.56 s; warm 0 to 30 ms) and proposed a wording of the exit criterion that records them. The user accepted both the numbers and the wording and decided that typed interop is the default for everything. The clang matrix (only clang 21 has run) and the interop corpus on a Windows host are still not shown; this ADR records them as risks, not as conditions.

## Decision

1. **`DefaultMode = Auto`.** A user who sets nothing gets the mode `auto`: typed interop when a clang++ is found, and Phase 04's opaque pipeline, **silently**, when it is not (`gocpp check -v` and `build -v` print one line that says which and why). The order of the sources is unchanged (flag, `GOCPP_INTEROP`, `GOCPP_TYPED_INTEROP`, default). `typed` without clang++ is still an error with status 3. The opaque mode and all three spellings stay: `-interop=opaque` and `GOCPP_INTEROP=opaque` give the old behavior, byte for byte, with no probe and no clang search. clang++ is still looked for only when a package that is not one of gocpp's own standard library packages imports a C/C++ header, so a program of Go alone, or one that imports only `fmt`, `os` and the like, pays nothing; a program that imports a C++ standard header such as `<vector>` is probed.
2. **The Phase 12 exit criterion is worded after the measurements** (ADR-121's proposal, Phase 12 README §5): warm builds add under 50 ms; typed probing of a package with C-style or its own headers, with the library header already made for its flags (any later check on a machine), adds under 0.5 s on an empty result cache; the first check on a machine, which makes that header, under 0.7 s; a package that includes large C++ library headers itself (`<algorithm>`, `<filesystem>`, `<map>`) is bounded by the compile of those headers, about 1.2 to 1.6 s.
3. **The test machinery keeps both pipelines.** The suites of `cmd/gocpp` and `tests` already pin `GOCPP_INTEROP=opaque` in their `TestMain` (the opaque pipeline is the contract of Phase 04 and their expectations are its); `TestCorpusTyped` runs the 294 programs that import headers in typed mode with both compilers; the default itself is pinned by `TestDefaultModeIsAuto` (`internal/typedinterop`), the `default` cases of `TestInteropPrecedence` and `TestInteropNoClang` (`cmd/gocpp`: typed with clang++, silent opaque without) and the `gocpp env` goldens.

## What the user sees

Measured with the binary of this branch on the shared 192-core machine at a load of 20 to 40 (so slower than ADR-121's quieter numbers), clang 21 for the probes, g++ 15 as the build compiler, medians of 5 to 7 runs, cold = the probe cache and its precompiled header off (`GOCPP_NOPROBECACHE=1`), warm = the probe cache filled; runtime and object caches warm in both modes:

| Program | `check` opaque / typed, cold | `check` opaque / typed, warm | `build` opaque / typed, cold | `build` opaque / typed, warm |
|---|---|---|---|---|
| `examples/raylib` | 65 ms / 844 ms | 40 ms / 110 ms | 1.06 s / 1.85 s | 1.01 s / 1.08 s |
| `examples/sqlite` | 59 ms / 823 ms | 41 ms / 109 ms | 1.35 s / 2.13 s | 1.32 s / 1.39 s |

A `gocpp build` of an unchanged program stops at the up-to-date check in 25 ms in both modes (the probes do not run). The warm numbers are above ADR-121's (0 to 18 ms over opaque) because of the load; the cold overhead is 0.78 s, above ADR-121's 0.65 s for the same reason. The two Windows demos, cross-built from Linux (`-os windows`, `<windows.h>`, `<d3d11.h>`, Dear ImGui's headers), are much heavier than the examples: `check` cold 0.61 s opaque and 6.6 s typed (`demos/imgui`), 0.93 s and 14.4 s (`demos/imgui-dx11`); warm 55 and 210 ms, 173 and 440 ms; a full build with warm caches 1.71 and 1.85 s, 4.99 and 5.38 s. A first build of a program with big Windows or framework headers is therefore several seconds slower, once per machine and header state.

Same output, same status: for the programs of `examples/` that import headers (`raylib`, `sqlite`, `cpp-std`, `mixed-sources`) `check`, `emit` and `build` exit 0 and print nothing in both modes; the programs that run (`sqlite`, `cpp-std`, `mixed-sources`) print what `output.txt` holds in both; `raylib` (needs a display) and the two demos were built, not run. What differs is the generated C++: `emit` of `raylib` and `sqlite` is byte for byte the same; for `cpp-std` and `mixed-sources` a call on a C++ value is `nums.push_back(4)` instead of `gp::deref(nums).push_back(4)` (typed knows the type, so it needs no dereference helper). The Windows demos build in both modes with the same status and no message; their `.exe` files differ in size by under 0.01 % (63 246 142 and 63 243 183 bytes for `imgui-dx11`).

New messages, listed honestly. For a **valid** program (one that opaque mode builds) none: the 294-program corpus has 0 typed errors, and no warning was printed for any example or demo. Typed mode adds diagnostics only for programs that are wrong: (a) errors in Go's words at the `.gp` line before the C++ compile, for a mistake in a call of C/C++ (`no overload of f matches the arguments`, `too many arguments in call to f`, `x.m undefined (type T has no field or method m)`, ...); with **g++ as the build compiler they are warnings** (clang found them, g++ may accept the code), and the C++ compile then usually also fails, so one mistake can show two messages; (b) the errors Go's own rules give where opaque mode let the C++ compiler decide, for example a void C++ call used as a value; (c) `gocpp: typed interop: ... (using opaque mode for P)` when a package cannot be probed, only with `-v` (the explicit `typed` prints it as a warning). Typed mode also **accepts** what opaque mode rejected: `var iv int = cmath.pow(10, 30)`, `v.at(0) = 5`, `[cstdio.BUFSIZ]byte`, a Go string passed to a `const char*` parameter (converted for you), and the promoted members of several embedded C++ types.

How to get the old behavior: `-interop=opaque` on any command that checks packages (`check`, `build`, `run`, `test`, `emit`, `vet`, `expand`), or `GOCPP_INTEROP=opaque` in the environment (a shell profile, a CI file, `gocpp.lsp.env` of the editor extension). `gocpp env GOCPP_INTEROP` shows `auto`.

## Without clang++, and the toolchain story

`auto` without a usable clang++ (not found, older than 17, or not working) is opaque with no message and no error; that is how every program built before this ADR. The user who has only g++ sees no change, and does not learn that typed mode exists unless a document or `-v` says so. What exists, per system (`internal/toolchain`, `internal/typedinterop/probe` `FindClang`/`FindClangFor`):

- **Nix** (the package and the dev shell): brings g++ 15 and clang++ 21, so typed mode is on and is the tested combination.
- **Linux without Nix**: gocpp downloads no compiler (the release archives say that a C++ compiler is needed: g++ 13+ or clang++ 17+). clang++ is searched in `GOCPP_CLANG`, then `PATH`. A user with g++ only is opaque. The documents now say so: README, `docs/guides/packaging.md` (install clang++ 17 or newer next to g++, 21 is the tested one, or set `GOCPP_INTEROP=opaque`), the release notes template (`.goreleaser.yaml`).
- **Windows**: `GOCPP_TOOLCHAIN=auto` uses a MinGW-w64 compiler from PATH or the usual folders (MSYS2, Chocolatey, Scoop, WinLibs) and downloads the pinned llvm-mingw, whose `x86_64-w64-mingw32-clang++` is a clang, only when there is none. The probes for windows/amd64 take, in this order, `GOCPP_CLANG`, `x86_64-w64-mingw32-clang++` in PATH, the build's compiler when it is clang (so the downloaded llvm-mingw), then `clang++` in PATH. A user who has no compiler gets the download and with it typed mode; a user with an MSYS2 or WinLibs **g++** gets neither a download nor typed mode (opaque, silent). Cross builds from Linux with the MinGW-w64 g++ use the host clang++ with the MinGW headers.
- **macOS** is not a target.

Recommendation (not done here, each a small follow-up): (1) the installer story for users who want typed mode on Linux is a line in the install instructions (`apt install clang`, `dnf install clang`) and on Windows `GOCPP_TOOLCHAIN=pinned` (always gocpp's llvm-mingw, about 80 MiB, which has the clang); (2) `gocpp env` could print the effective mode and the clang it found (`interop: typed (clang++ 21.1.8)` or `opaque (no clang++ found)`) so that "why is my build not typed" has an answer without `-v`; (3) the first typed check could make the library header (the 0.4 s of the cold cost) in the background from any gocpp command that sees a header import, as ADR-121 suggested; (4) the nightly matrix of ADR-108 (clang 17 to latest) is still wanted: a default makes it more urgent.

## The language server

The server takes its mode from the same `ResolveMode`, in two places (`internal/lsp/cache`: the header-name indexer and the member indexer). Both are off only for `opaque`, so with the new default they run for every project that imports a header and has a clang++: a background worker pool (`maxProbes`) runs clang for completion after a header package or namespace, for member completion and for the declarations behind hover and definition. **Nothing waits on clang**: a request reads completed immutable facts (`HeaderSymbols`, the member facts, the declarations of a name) and does not call the runner, check files or schedule work; a missing or failing clang leaves the existing answers and costs one silent retry; the byte budgets of the caches (32 MiB and 128 entries for header indexes, the member index budget) and the cancellation at shutdown are those of 12.13. The background cost in the editor (ADR-122: "the cost is background only") was measured with these workers on (`GOCPP_INTEROP=typed` in the server's environment), so the request paths do not change; the speed budgets of the other Phase 11 rows were not re-measured here; the unit tests of `internal/lsp/cache` and `internal/lsp/server` pass with the new default. The server's constants hook and the interop checker are not used (typed-interop.md §13.4), so the editor's diagnostics do not change. What does change: an editor on a project with headers starts clang++ processes in the background (at most `maxProbes` = 2 index workers at a time, results cached on disk) on the first open and after a header changes, where it started none before. `GOCPP_INTEROP=opaque` in the server's environment turns it off.

## Risks

1. **The cold cost is large for header-heavy programs.** The examples pay 0.5 to 1.6 s on the first build; the Windows demos 6 to 14 s of probing on a cold cache (a loaded machine; the library header is retained after the first run). A user who measures the first build of a framework program against opaque mode sees it. A later program on the same machine reuses the header and the cache; the cold cost comes back after a header changes, a compiler changes or the cache is cleared.
2. **Only clang 21 was tested.** A user with clang 17 to 20 (the documented minimum) is typed now. The reader of clang's JSON is tolerant and a probe that fails leaves its package opaque (with `auto`, silently; `-v` says so), but a different dump can give a wrong answer, and a wrong early error is an error (a warning with g++). `tools/clang-matrix.sh` exists; no matrix has run. The package docs recommend 21 for the tested combination.
3. **Windows hosts.** The probe for a Windows host ran on the real PC with the pinned llvm-mingw's clang (`TestWindowsTypedNative`), but the interop corpus has not run there in typed mode.
4. **The same source builds different C++ on different machines** (typed where clang++ is installed, opaque where not). The programs print the same, but `gocpp emit` output, object-cache keys and the `-v` line differ between a developer's machine and a CI machine without clang. A project that wants one behavior sets `GOCPP_INTEROP` (CI files, `Makefile`).
5. **Typed checks are warnings with g++ and errors with clang++.** A project built with clang++ can get an error from the checker (a false positive would block a build that the compiler accepts); the compatibility rule and the corpus say this does not happen for the 294 programs, which is not a proof. `-interop=opaque` is the escape.
6. **The test suites do not run the default.** `cmd/gocpp` and `tests` pin opaque (see below), so a regression that only appears in the default pipeline of a command is found by `TestCorpusTyped` and the few default cases, not by the 2000 programs of `TestRun`.
7. **Disk and processes.** The probe cache and up to four precompiled headers (about 8 MB each) live under the user's cache folder; every typed build and the editor start clang++ processes bounded by `GOCPP_PROBE_JOBS`.

## Where the old default is still assumed

Tests that deliberately test the opaque pipeline set `GOCPP_INTEROP=opaque` themselves and are unchanged: the `TestMain` of `tests` (every suite: `TestRun`, `TestInterop`, `TestZoo`, `TestErrors`, `TestGolden`, ...) and of `cmd/gocpp`, `TestTypedRun`'s opaque halves (`typedrun_test.go`, `typedemit_test.go`, `typedconsts_test.go`, `typedpromoted_test.go`), `TestInteropUpToDate` (the up-to-date key), `internal/lsp/server/foreignhover_test.go` and `internal/lsp/cache/headerindex_test.go` (the opaque cases). The opaque lowering's messages ("a C/C++ macro in an array length ... needs typed interop (install clang++ 17 or newer, and do not use -interop=opaque)", the phase-12 gates in the feature matrix) say the same as before, except that the hint no longer tells the user to pass a flag that is automatic now: with the new default they are what a user without clang++, or with `-interop=opaque`, gets, and tests and `gocpp explain` key on them.

## Alternatives considered

- *Keep opaque until ADR-108's three measurements pass.* The earlier plan; replaced by the user's decision.
- *Typed only (drop opaque).* Rejected again (ADR-108 option 4): it makes clang a hard requirement and breaks the compatibility rule.
- *`typed` as the default (an error without clang++).* Rejected: a program that built on a machine with only g++ must keep building there.
- *Warn once when typed mode is unavailable.* Not done: ADR-101 chose silence so that scripts and CI output do not change; `-v` and a documented `gocpp env` line (follow-up 2 above) are the way to find out.
