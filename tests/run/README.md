# tests/run

A run test is one `.gp` program. The harness runs it in this folder with
`gocpp run file.gp`, once per C++ compiler. It passes when stdout matches the `// Output:` block
at the end of the file, the exit code is the expected one, and stderr is what the test allows.

[slices_append.gp](slices_append.gp):

```go
// phase: 03

package main

import "fmt"

func main() {
	s := []int{1, 2}
	t := append(s, 3)
	s[0] = 9
	fmt.Println(s, t, len(t), cap(t) >= 3)
}

// Output:
// [9 2] [1 2 3] 3 true
```

| Line | Where | Meaning |
|---|---|---|
| `// phase: NN` | the first line | the phase that makes the test pass; until then the test is skipped |
| `// ExitCode: N` | the top of the file, before the package clause | the expected exit code, 0 to 255 (default 0). A panic exits with 2, like Go |
| `// Stderr: regexp` | the top of the file, before the package clause | stderr must match this Go regexp. It is unanchored; `(?m)` makes `^` and `$` match at every line. A test may have several, and each must match. **Without one, stderr must be empty**; `// Stderr: .*` accepts anything |
| `//go:build expr` | the top of the file, before the package clause | a normal Go build constraint: where it excludes the target, the test is skipped ([tests/README.md](../README.md)) |
| `// lsan: cycle` | the top of the file, before the package clause | the program leaks a reference cycle on purpose (D1), so a sanitizer run turns LeakSanitizer off for it ([tests/README.md](../README.md#sanitizers)) |
| `// zoneinfo: required` | the top of the file, before the package clause | the program loads time zones by name (`time.LoadLocation`): the test is skipped on a machine without a time zone database ([tests/README.md](../README.md)) |
| `// divergence: Dn` | the top of the file, before the package clause | the program shows divergence Dn of [docs/spec/language.md](../../docs/spec/language.md), so real Go prints something else: `TestRunVsGo` skips it, and its output can't come from Go (write what gocpp must print, and why, in the test's comment) |
| `// Output:` | the end of the file | the expected stdout, as in a Go example test (below) |

The `// Output:` block works like the one of a Go example: each comment line after it is one
line of output, without the `//` and one space after it, and `//` alone is an empty line. Text
on the `// Output:` line itself is the first line (`// Output: hello`). Only comment lines may
follow it. As in Go, space at the start and at the end of the whole output doesn't count;
everything in between must match exactly. Spaces at the end of a comment line are dropped
(gofmt drops them too), so output with spaces at the end of a line needs a
[diff test](../diff/README.md). A program that prints nothing ends with `// Output:` alone.

A test of a program that panics (the message is Go's):

```go
// phase: 03
// ExitCode: 2
// Stderr: ^panic: runtime error: index out of range \[5\] with length 3

package main
```

For a program that Go can run too, take the expected output from real Go, never from memory
([docs/CONTRIBUTING.md](../../docs/CONTRIBUTING.md) §3 shows how), or make it a
[diff test](../diff/README.md), where real Go is the reference by itself.
`GOCPP_RUN_VS_GO=1 go test ./tests/... -run RunVsGo` checks every run test that Go can build
against real Go: its output, its exit code and its `// Stderr:` lines
([tests/README.md](../README.md)). A test that needs a
C/C++ library goes into [tests/interop](../interop/README.md).

The `fmt_*.gp` tests (except the nine older ones) are generated by [tools/fmtcorpus](../../tools/fmtcorpus), whose Go
sources run in real Go to write the `// Output:` blocks.

## Programs with `!`

The `must_*.gp` tests (Phase 10) use `!`, which Go cannot build. Each has a **twin**, the same
program as a Go programmer writes it with `if err != nil`, in [testdata/must_twin/](testdata/must_twin) under the
same name (`must_call_basic.gp` has `testdata/must_twin/must_call_basic.go`). `TestRunVsGo` runs the twin
with real Go in place of the `.gp` file, so the `// Output:` block, the exit code and the
`// Stderr:` lines of a program with `!` are what real Go does with the hand-written code
([musttwin_test.go](../musttwin_test.go)). A twin that needs `errors.Wrapf` (gocpp's own) defines it
in the file, and one that needs the end of `func main!()` prints `<program>: <error>` and calls
`os.Exit(1)` itself.

`must_gen_NN.gp` are generated by [mustgen](../mustgen/main.go), which writes the program, the
twin, and the output of the twin (`go run ./tests/mustgen -n 20 -seed 1 -out tests/run`). Run
them with `GOCPP_TEST_PHASE=10`, like every `// phase: 10` test.

## Programs with user macros

The `umacro_*.gp` tests (Phase 10, step 10.9) use `macro`, `lazy` and `#Name(...)`, which Go cannot build.
Each has a **twin** in [testdata/macro_twin/](testdata/macro_twin) under the same name: the program with
every macro written out the way the compiler does it (the macro is a function with the file, the line, the
function and the text of the arguments as parameters, a lazy argument is a func literal, a wrap macro's code
is a func literal with named results), as plain Go. `TestRunVsGo` runs the twin with real Go, so the
`// Output:` block of a macro program is what real Go prints for the hand-expanded code, as for `!`
([musttwin_test.go](../musttwin_test.go)). The twin writes the places that the compiler would pass
(`"umacro_wrap.gp"`, line 66, `"main.secret"`) as literals, so a change to the lines of the `.gp` file needs the same
change in the twin. A multi-package macro test is a folder of [tests/pkgs](../pkgs/README.md) (Go can't build
it, so it has no twin: its output was checked with a hand-expanded Go module).
